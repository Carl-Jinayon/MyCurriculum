> This document is self-contained. It transfers the complete identity of one learner's
> CS mastery curriculum — vision, mission, principles, capability goals, and topics —
> to any AI, coach, or collaborator. No other files are required to understand this system.

## 1. Identity

This is a **long-term, AI-era Computer Science mastery system** for ONE learner:

- 20 years old, third-year CS student in the Philippines, ~2 years from graduation
- University instruction is weak — self-study is the primary education path
- 3–5 hours/day available for self-study, excluding university obligations
- Complete beginner in programming and mathematics (assessed)
- Strong interest: software development, AI engineering, machine learning, mathematics
- Uses AI (OpenCode) heavily as a learning and engineering tool
- Ambition: technically exceptional — not merely employable — and globally competitive

This is NOT a university degree, NOT a bootcamp, NOT an ML course. It is a
dependency-driven mastery path designed for the AI era, where AI can generate code
but humans must understand, verify, judge, and design.

## 2. Vision

> Become an exceptional Computer Science student before graduation — with strong
> fundamentals, real engineering ability, a strong portfolio, AI-era technical skills,
> and enough practical capability to be employable early — and continue toward
> advanced mastery after graduation.

"Top 1%" here does NOT mean memorizing everything. It means unusually strong
capability across the dimensions that matter: understanding, implementation,
verification, independence, judgment, and adaptability.

The learner's long-term trajectory is sequential, not simultaneous:

```
CS foundations → strong programmer → software/full-stack engineer
→ AI-native engineer → ML/applied AI specialist → advanced professional → specialization
```

## 3. Mission

Build, before graduation:

- Strong CS fundamentals (DSA, systems, networking, databases, architecture, security)
- Strong programming and problem-solving ability
- Real software engineering ability (Git, testing, debugging, deployment, CI/CD)
- A professional portfolio demonstrating judgment, not course completion
- AI-native engineering skill: directing AI agents, verifying AI output, knowing when AI is wrong
- Appropriate mathematics foundations, learned just-in-time
- Technical interview readiness and freelance capability when earned
- Independence: the ability to learn any new technology without being told what to study

## 4. Core Principles

1. **ONE curriculum, ONE active objective.** Never run competing curricula in parallel.
   Other subjects support the current objective; they are never separate tracks.
   Every day answers: "What is the highest-value thing to learn next?"

2. **Mastery over completion.** Finishing lessons, reading notes, or producing AI-generated
   code is NOT learning. Mastery means demonstrated capability: running code, passing tests,
   explaining from memory, transferring to new problems.

3. **Verification-first.** Evidence beats claims. Code without execution is not proof.
   "I think it works" is not "I verified it works." Always verify: current file, current run,
   current output.

4. **AI is an accelerator, never a replacement.** The learner must move up the AI ladder:
   AI can do it → I understand it → I can verify it → I can do it independently →
   I can teach it → I can design systems around it → I can direct AI agents reliably.
   The goal is an AI-native engineer, not an AI-dependent programmer.

5. **Doing is learning.** Prefer: small explanation → attempt → failure → debugging →
   reflection → deeper explanation → application. Never long lectures without implementation.

6. **Just-in-time mathematics.** Math is introduced when foundational, when the current
   technical path requires it, or when it deepens understanding — never dumped early.
   Sequence (adaptive): algebra → functions → logic → discrete math → probability →
   statistics → linear algebra → calculus → optimization.

7. **Continuous threads.** Security, testing, debugging, Git, systems thinking, and AI
   collaboration are taught in context across ALL stages — not as isolated courses.

8. **The roadmap is a map, not a prison.** Dependency-aware and adaptive: master fast →
   deepen; struggle → remediate; missing prerequisite → learn it temporarily;
   career opportunity → adapt. But changes must be evidence-based, not constant redesign.

9. **Spaced recall and mistake logging.** Important concepts return. Mental-model errors
   are logged (what was believed / what is true / why reasoning failed / correct model /
   example / how to recognize) and re-checked. Typos are never logged; wrong mental models are.

10. **Evidence-based assessment.** No fabricated scores. Qualitative levels:
    Weak / Developing / Competent / Strong / Advanced / Exceptional for current stage —
    always with the evidence behind the judgment. Maintain KNOWN vs PROBABLY KNOWN vs UNKNOWN.

11. **Security from day one.** Input validation at the start; web security, secrets,
    and AI security (prompt injection, tool abuse, data leakage) as the learner advances.
    Never trust user input.

12. **No over-engineering of the learning system.** No dashboards, trackers, or bureaucracy.
    Learning > managing learning. One objective, real implementation, honest records.

## 5. Capability Dimensions (the AI-era human skills)

Beyond subjects, the curriculum deliberately builds capabilities that remain valuable
when AI can generate most code:

- Problem formulation and specification (turning vague needs into precise requirements)
- Architecture and system design judgment (choosing structures and tradeoffs)
- Verification: testing, evaluating, and proving that systems work
- Debugging: systematic isolation of causes from symptoms
- Reading primary sources: official docs, RFCs, source code, papers
- Evaluating AI output: detecting hallucinations, subtle bugs, wrong assumptions
- Context engineering: giving AI agents precise tasks, constraints, acceptance criteria
- Knowing when NOT to use AI, and when AI is the wrong tool
- Technical communication: explanations, documentation, code review
- Independent learning: encountering an unfamiliar technology and self-directing its study
- AI-free checkpoints: periodic independent work (programming, algorithms, math, design
  reasoning) with no substantial AI assistance, to prove the underlying ability is real

## 6. Topics — Full Subject Map

### Continuous threads (all stages)
Security, testing, debugging, Git/GitHub, mathematics (just-in-time), AI collaboration
(Level 1 basic assistance → Level 5 professional AI engineering), systems thinking.

### STAGE 0 — Foundations (~130–160h)
Learning how to learn; algebra & functions; logic; discrete foundations (sets,
combinatorics); Python fundamentals (variables, types, conditionals, loops, functions,
lists, errors, file I/O); terminal/command line; Git & GitHub basics; testing/debugging basics.

### STAGE 1 — Programmer / Problem Solver (~160–200h)
Data structures (lists, stacks, queues, linked lists, hash tables, trees, graphs);
algorithms (search, sort, recursion, greedy, dynamic programming); complexity analysis
(Big-O); object-oriented programming; exceptions; testing with pytest; debugging mastery;
introductory probability; Git workflows.

### STAGE 2 — Junior Builder (~200–260h)
Databases & SQL (modeling, queries, joins, indexing, transactions); web fundamentals
(HTTP, HTML, CSS); JavaScript & DOM; frontend development; backend development
(Flask/FastAPI, REST, JSON); authentication & authorization; linear algebra foundations;
deployment basics; first serious projects; initial freelance readiness.

### STAGE 3 — Software / Full-Stack Professional (~260–320h)
Production full-stack applications; advanced backend (rate limiting, caching, background
jobs); web security (XSS, CSRF, SQL injection, secrets); deployment & operations (Linux,
Docker, cloud); CI/CD; observability (logging, monitoring); system design fundamentals;
integration testing; calculus; capstone project; job/freelance readiness.

### STAGE 4 — AI-Native Engineer (~220–280h)
LLM APIs (prompting, structured output); embeddings; retrieval & RAG; agents & tool
calling; evaluation; AI reliability; AI security (prompt injection, tool abuse, data
leakage, agent permissions); AI product architecture; context engineering; production
AI projects.

### STAGE 5 — ML / Applied AI Specialist (~260–320h)
Probability & statistics; linear algebra deep; calculus & optimization; classical ML
(regression, classification, clustering, trees, ensembles); neural networks & deep
learning; training & fine-tuning; model evaluation; MLOps; end-to-end ML projects.

### STAGE 6 — Advanced Technical Professional (~220–280h)
Distributed systems (consistency, replication, consensus); advanced architecture;
advanced security; scalability & reliability (SLOs, failure modes); specialization
depth; technical communication (design docs, code review).

### STAGE 7 — Open-Ended Branches
ML/AI research; AI security; cybersecurity; data engineering; cloud/platform
engineering; quantitative computing; robotics/embedded; systems; technical leadership;
technical entrepreneurship.

Hours are estimates, not deadlines. Ordering is dependency-driven.

## 7. Methodology

- **Lesson format** (every substantial topic): Objective / Why It Matters / Plan /
  Learning Material / Practice / Build / AI Interaction / Verification / Mastery Check /
  Reflection.
- **Three files per topic**: Full lesson reference; Cheat Sheet (short recall);
  Advanced file (strictly optional: advanced content, explore-it-yourself experiments,
  where the topic leads).
- **Exercises + projects**: daily practice in exercise folders; portfolio projects that
  progress from tools → apps → full-stack → production-like → AI applications → ML →
  flagship project. Projects must demonstrate engineering judgment, testing, documentation,
  and honest AI-usage disclosure.
- **University strategy**: university is a constraint, not the curriculum. High-value
  topics integrate deeply; low-value topics pass efficiently; redundant material is not
  duplicated. Pass reliably; invest serious effort in the master curriculum.
- **Career strategy**: employability before graduation; freelance only when capable of
  reliably delivering useful work; portfolio-driven opportunities; internships; interviews
  near graduation.
- **AI-free checkpoints**: periodic independent work to prove real ability.
- **Teaching style**: direct, honest, technical, evidence-based. No empty praise; precise
  correction of wrong reasoning; hints before answers when testing the learner.

## 8. Success Metrics

The ultimate question: **What can the learner actually do?**

Measured across: understanding, implementation, verification, independence, transfer,
engineering judgment. Evidence sources: executed code, tests, debugging, from-memory
explanations, predictions, transfer problems, independent work, portfolio quality,
employability.

Knowledge states: KNOWN (demonstrated) / PROBABLY KNOWN (exposure, insufficient
evidence) / UNKNOWN (not demonstrated). When uncertain, test.

Portfolio test: does it demonstrate professional capability, or merely course completion?
Replace weak projects.

Employability checkpoints (periodic): could this learner deliver useful work for another
person? Early: scripting/tools. Intermediate: websites, APIs, database apps. Advanced:
deployed systems, AI applications. Near graduation: portfolio, interviews, resume.
